Guided tour · fictional data

The Portal Tour —
five screens that see your agents

Five portals surface AI agent security, each seeing a different slice of the estate. This page walks the screens in the order an assessment would, with representative numbers from a fictional tenant (Contoso, 84 agents) and the KQL behind each check. All figures are fictional. Four of these screens count agents — and they disagree by design, so always note which screen a number came from.

Stop 1 · security.microsoft.com

Security Dashboard for AI

The aggregate view: discovered AI assets, misconfigurations, and sensitive-interaction counts, with delegatable recommendations. Needs Agent 365 or E7 for the full experience; local-agent discovery populates regardless on MDE P2.

⚠ What a real tenant's first look tends to surface

Agents changed to No Authentication recently — any tenant user can change an agent's auth type regardless of ownership; enable the change-detection Analytics Rule from Playbooks. And a majority of Copilot Studio agents being Classic (61 of Contoso's 84) — pre-Agent-ID agents with zero Entra security coverage; see Identity.

Stop 2 · Defender Advanced Hunting

The AgentsInfo inventory — every platform, including local

The widest single view. Cloud agents populate with Agent 365; locally installed agents (coding CLIs, desktop AI) populate on MDE P2 alone with Platform == "LocalAgents". The table stores snapshots — always reduce with arg_max and drop deleted agents:

// Current live inventory
AgentsInfo
| summarize arg_max(Timestamp, *) by AgentId
| where LifecycleStatus != "Deleted"
| project AgentName, Platform, PublishedStatus, ToolsAuthenticationType, Owners
// The two lists worth reading first: no-auth and ownerless
AgentsInfo
| summarize arg_max(Timestamp, *) by AgentId
| where LifecycleStatus != "Deleted"
| where tostring(ToolsAuthenticationType) has "None"
or isempty(tostring(Owners)) or tostring(Owners) in ("", "[]")
| project AgentName, Platform, ToolsAuthenticationType, Owners, CreatedDateTime
Stop 3 · admin.microsoft.com

The Agent Registry

Agents → All agents → Registry: the published catalogue — Microsoft agents, partner-built, your org's own, and shared-by-creator — with local agents now surfacing in public preview (publisher, device count, last scanned). Viewing needs only the AI Administrator or AI Reader role, no licence. The registry counts published titles: it is blind to locally installed agents and can disagree with its own API for the same tenant.

Stop 4 · entra.microsoft.com

Entra Agent ID

The identity view: agent identities under their blueprints, with sponsors and lifecycle. Readable at any Entra tier — Conditional Access, ID Protection and governance for agents are what Agent 365 adds. Classic agents never appear here; enumerate them by the service principal tag AgentCreatedBy:CopilotStudio.

Stop 5 · Sentinel

Where the deep telemetry lands

Two public-preview connectors land the richest data lake-side: the Agent 365 connector (runtime spans in UnifiedAgentObservability — prompts, tool arguments, session reconstruction) and the Microsoft Agent Identities connector (the four-table identity graph). Both need the data lake tier — a separate purchase. The Agent Telemetry Map charts exactly which agent type emits to which of the four query surfaces, behind which licence.

Setup

Getting from zero to these screens

Enable the Defender + Power Platform integration for Copilot Studio discovery → local-agent discovery runs automatically on MDE P2 onboarded devices → enrol in Agent 365 for the cloud-agent side → instrument custom agents with the Agent 365 SDK → connect Sentinel (Copilot connector, Defender XDR, and the two lake connectors). The full sequencing lives in the six-phase rollout and Playbooks.
