The money question

What licences
actually gate what

Licensing runs on three independent axes, and movement on one never implies coverage on another. Most AI security budgeting errors are one of two assumptions: that an M365 purchase covers Azure AI workloads, or that Agent 365 includes the Sentinel data lake. Neither is true.

AxisBilledWhat lives here
Microsoft 365Per userCopilot audit, Purview, Defender XDR, Agent 365 / E7 — the agent control plane
Azure — Defender plansPer resource + per tokens scannedFoundry and Azure OpenAI workload security (surface 2)
SentinelIngestion, retention, and the data lake tierSIEM correlation — and the lake tier that carries the deepest agent telemetry. Agent 365 writes into the lake; it does not include it
The split that causes the most confusion

One table, two populations, two licences

⚠ An empty result can be a licence boundary, not a data gap

AgentsInfo — local agents populate on E5 / MDE P2 with no Agent 365 licence (tenant-verified); cloud agents need Agent 365.
CloudAppEvents — Copilot interaction verdict rows (Jailbreak, XPIA) arrive on E5; the Agent 365 runtime rows (InvokeAgent, InferenceCall, ExecuteToolBy*) do not exist until Agent 365 instruments an agent.

📌 Two rules for quoting any of this

Never quote a price from a web page — including this one; verify against the current Microsoft price list. And when a screen shows nothing, check the licence gate before declaring a data gap — the Agent Telemetry Map carries the gate on every table for exactly this reason.
